# X（Twitter）投稿ネタ ストック

「スイーツムツム」の告知用。上から順に使い切る必要はなく、**その日出せるものを1つ**選んで投稿する。

## 運用ルール（先に読む）

- **1日1〜2投稿まで**。新規アカウントの連投は凍結リスクが高い
- **動画/GIF付きが最も伸びる**。文字だけの投稿は埋もれる
- 自動投稿はしない（X規約違反＋凍結リスク）
- リンクは固定ポストかリプライに置くと本文が伸びやすい（本文にURLがあると表示が抑えられる傾向）
- ハッシュタグは**2〜4個**まで。付けすぎは逆効果

**共通タグ**: `#個人開発` `#インディーゲーム` `#iOSゲーム` `#ゲーム開発`
**ストアURL**: https://apps.apple.com/jp/app/id6790820886

## B. 開発の裏側（個人開発クラスタに刺さる）

**B-1 物理演算の作り直し**
```
「なんちゃって物理演算」だったのを、根本から作り直しました。

・落下に重力を入れる
・着地の沈み込みを強調
・崩れる時はMatter.jsに引き渡す

積み上げゲームは"崩れ方"が命だと思っています🍩
```

**B-2 チュートリアルの設計**
```
操作が分からない問題、どう解決するか悩みました。

止めて説明する？→ テンポが死ぬ
マリオは何も説明しない → でも1-1が実質チュートリアル

結論：ゲームは止めず、指と矢印だけ出して
スワイプしたら即消える形にしました。
```

**B-3 難易度のバランス**
```
落下スピードを上げると理不尽になる。
でも簡単すぎても飽きる。

なので「落下は遅く、落ちる位置をブレさせる」に変更。
速さじゃなく"狙いの難しさ"で難易度を作る方針です🍩
```

**B-4 描画パフォーマンス**
```
スコア表示のすりガラス（backdrop-filter）、
見た目はいいけど毎フレーム再合成されるので重い。

常時表示されるUIからは外しました。
かわいさと軽さの綱引き…🍰
```

## 投稿に添える素材の作り方

- **プレイ動画**: iPhoneの画面収録（設定 → コントロールセンター → 画面収録）
  ※音は44.1kHz統一済みなので倍速バグは解消済み
- **GIF化**: 動画をそのまま投稿してもよい（Xは動画の方が再生されやすい）
- **スクショ**: `appstore-screenshots/` の素材を流用できる
